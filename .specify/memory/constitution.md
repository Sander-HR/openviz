# OpenViz Constitution

## Core Principles

### I. Type Safety (NON-NEGOTIABLE)
No `any`. No `@ts-ignore`. Every change must pass `tsc` with zero errors.
Types live in `src/types/` or colocated `[ComponentName].types.ts`. If a value
cannot be typed without `any`, the design is wrong — stop and restructure.

### II. Test-First, Layered (NON-NEGOTIABLE)
TDD is mandatory for new work, applied per layer:
- **Logic layers** (services, hooks, store slices, utils): strict red-green —
  write the failing test first, then implement to green. No exceptions.
- **Components**: behavior tests derived from the spec's acceptance criteria
  are written before implementation (React Testing Library). Pixel-level Konva
  canvas rendering is verified via behavior tests + manual dev-server checks,
  not forced unit tests.
- The coverage floor may never regress. `lint + tsc + vitest` must be green
  before any merge; CI enforces this.

### III. State Architecture
- Global client state: **zustand** slices in `src/store/`.
- Server state: **react-query** — no manual fetch/caching in components.
- All `useEffect` and `fetch` calls belong in `use[Feature].ts` hooks, never
  inline in view components.

### IV. Styling & UI Primitives
Tailwind CSS only — no inline styles, no CSS modules, no styled-components.
Accessible primitives (menus, dialogs, context menus) come from **Radix UI**;
animations/transitions use Framer Motion. Canvas rendering uses Konva.js via
react-konva; the workbench node graph uses React Flow.

### V. Module Boundaries & File Limits
Files exceeding 300 lines must be split by concern: Logic / View / Types.
Named exports only (no default exports). Absolute imports (`@/features/...`,
`@/store/...`) preferred over relative `../../`. Folder mapping is law:
interfaces/types → `src/types/`; business logic/API → `src/services/`;
state → `src/store/`; pure UI → `src/components/`.

## Technology Stack Constraints
- React 19, TypeScript (strict), Next.js app runtime (repo is mid-migration
  from Vite — do not introduce a second bundler entry point).
- ComfyUI integration goes through `src/services/` only; no direct canvas
  API calls from components.
- Database: Postgres via Drizzle ORM; schema changes require generated
  migrations, never hand-edited SQL in app code.

## Development Workflow & Quality Gates
- New ideas enter through **idea assessment** (`/speckit.assess.*`); only a
  **go** verdict proceeds to specification.
- Features follow SDD: `/speckit.specify → clarify → plan → tasks → analyze →
  implement → converge`, on a numbered feature branch created via
  `/speckit.git.feature` (`NNN-slug`).
- Every task in `tasks.md` that touches a logic layer names its test file
  first. Implementation commits must keep CI green.
- Quality gates per merge: ESLint clean, `tsc --noEmit` clean, full vitest
  suite green, coverage floor not regressed.

## Governance
This constitution supersedes all other development practices in this
repository. `AGENTS.md` is the runtime guidance file and must stay consistent
with it; conflicts resolve in favor of this document.

Amendments require: a version bump (MAJOR for new/removed principles,
MINOR for clarifications), a committed diff to this file, and an explicit
team decision recorded in the commit message. All plans generated by
`/speckit.plan` must cite compliance with these principles.
